# 부자할미 타이쿤 — Phase 1–4

React + Vite + TypeScript / Tailwind CSS / Lucide / Zustand persist.

```sh
npm install
npm run dev
```

검증:

```sh
npm run build     # 타입 검사 및 프로덕션 빌드
npm test          # 날짜·투자·XP·정산·표정·스토어 검증
npm run test:e2e  # 설치된 Google Chrome으로 데스크톱·모바일 브라우저 검증
```

주요 파일:

- `src/types/index.ts`: 전체 도메인 타입과 데이터 스냅샷 인터페이스
- `src/store/index.ts`: 상태 변경 액션, 입력 검증, LocalStorage 영속화
- `src/App.tsx`: 반응형 5개 탭
- `src/components/GoalsAndSettingsTab.tsx`: 연간/월간 목표, 기간 선택, 예산 코드 CRUD
- `src/components/CalendarTab.tsx`: 월간·주간·일간 가계부, 입력 모달, 삭제 확인, 일일 XP 토스트
- `src/components/StatisticsTab.tsx`: 월별 수입·지출·저축 비교, 예산별 사용률과 초과 표시
- `src/lib/calendar.ts`: 윤년, 월별 일수, 날짜 이동과 일요일 기준 주간 계산
- `src/lib/finance.ts`: 월별 거래 필터, 유형별 합계, 예산별 사용률

가계부는 입력한 날짜 기준으로 기록합니다. 날짜 산술은 UTC를 사용해 일광 절약 시간 전환의 영향을 피하고, 오늘 날짜는 브라우저의 현지 날짜를 사용합니다. 월간 달력의 날짜를 선택하면 하단에 상세 기록이 표시됩니다. 주간은 일요일부터 토요일까지이며, 일간 보기에서 수입·지출·저축 내역을 확인하고 삭제할 수 있습니다. 작은 화면의 월간 달력은 천·만 단위의 축약 금액을 표시하며, 선택한 날짜의 상세 내역에서 정확한 금액을 확인할 수 있습니다.

`saveTransactionWithDailyReward`는 거래, XP 이력, 캐릭터를 하나의 상태 갱신으로 저장합니다. `DAILY_LOG + txDate` 이력이 없을 때만 10 XP를 지급하며, 같은 날짜의 추가 입력이나 거래 삭제 후 재입력에는 중복 지급하지 않습니다. 과거 날짜를 기록해도 거래 날짜를 기준으로 지급 여부를 판단합니다. `earnedDate`는 실제 지급일입니다. `saveTransaction`은 XP 없는 기본 저장 액션으로 유지됩니다.

수입은 에메랄드와 `+`, 지출은 코랄 레드와 `-`, 저축은 인디고로 구분합니다. 통계의 저축은 지출에 포함하지 않습니다. 예산 사용률은 선택 월의 지출과 현재 설정한 월 한도를 비교합니다. 한도 초과 시 막대를 빨갛게 표시하며, 0원 한도에 지출이 있으면 초과로 처리합니다.

목표 초기값은 미설정이며, 0을 입력해 명시적으로 저장할 수 있습니다. 기본 예산 코드는 5개입니다. 코드 변경 시 연결 거래의 참조를 함께 갱신하며, 사용 중인 코드는 삭제할 수 없습니다. INCOME/SAVING은 기본 거래용 예약 코드입니다. 목표 설정 저장 자체는 XP를 지급하지 않습니다.

레벨과 집은 누적 XP에 따라 상승합니다. 아래 Phase 4의 구간을 사용하며 기존 저장 데이터도 누적 XP로 이전합니다.

Firebase 전환 시 `AppData`를 repository의 읽기/쓰기 스냅샷으로 사용하고, actions와 원격 동기화 계층을 분리할 수 있습니다. 현재 데이터는 이 브라우저의 LocalStorage에 저장됩니다.


## Phase 3 투자 포트폴리오

- `src/data/stocks.json`: 한국 주식, 나스닥, ETF, 금 ETF 20개 샘플. 전체 지수 구성 종목이나 ETF 순위 목록이 아닙니다. 한국어 별칭·티커·영문명으로 검색합니다. 금은 실물 금 ETF인 GLD를 사용하며 원금과 수량의 단위는 USD와 주입니다.
- `src/utils/financeApi.ts`: `fetchCurrentPrice(ticker)`는 Yahoo의 `regularMarketPrice` 또는 실패 시 `null`을 반환합니다. `{includeMetadata: true}` 옵션은 가격, 통화, 거래 기준 시각, 조회 시각을 반환합니다.
- `src/components/InvestmentTab.tsx`: 키보드 자동완성, 원금·실제 보유 수량 입력/수정, 월별 기록, 시세 갱신, 종목별 수익률과 전월 대비, 통화별 요약입니다.
- `src/lib/investments.ts`: 보유 수량 기반 평가, 월별 스냅샷 이월, 전월 대비 계산과 오래된 응답 보호입니다.

사용자가 선택한 방식에 따라 실제 보유 수량을 입력합니다. 평균 매수 단가 = 매수 원금 / 수량, 평가금액 = 현재가 × 수량, 수익률 = (현재가 / 평균 매수 단가 − 1) × 100입니다. 원금은 거래 통화로 입력합니다. 원화·달러는 각각 합산하며 환전 합계나 환율 손익, 세금·수수료·배당은 계산하지 않습니다.

### CORS와 조회 실패

클라이언트는 Yahoo에 직접 요청하지 않고 공개 [AllOrigins](https://allorigins.win/) `/raw?url=...` 엔드포인트를 사용합니다. 실패하면 `/get?url=...`의 JSON 래핑 응답으로 재시도합니다. 정적 프로덕션 빌드는 이 공개 프록시 경로를 사용합니다. 로컬 Vite 개발 서버에서는 `/api/finance/chart/{ticker}`가 같은 공개 프록시를 대신 호출하는 동일 출처 경로를 우선 사용해 브라우저 직접 요청의 시간 초과도 보완합니다. 이 경로는 임의 URL을 받지 않으며 허용 형식의 티커만 받습니다. API 키나 추가 서버 설정은 필요하지 않습니다. 프록시에는 티커 조회 URL만 전달합니다.

요청마다 8초 제한을 두고 HTTP 오류, JSON 파싱 실패, 잘못된 종목·통화·가격·거래 시각을 처리합니다. 30초 메모리 캐시와 동시 요청 중복 방지가 있으며 수동 새로고침은 캐시를 우회합니다. 등록 종목은 `Promise.all`로 병렬 조회합니다. 비공식 Yahoo 엔드포인트 및 공개 프록시의 가용성은 외부 서비스에 의존합니다.

기존 종목의 조회가 실패하면 저장 평가금액을 유지합니다. 신규 종목이 시세를 한 번도 받지 못했다면 원금을 임시 평가금액으로 표시하고 수익률을 미확인으로 표시합니다. 가짜 시세는 만들지 않습니다. 첫 성공 시 자동으로 시세 기반 평가로 바뀝니다. 정규장 가격이며 [Yahoo 안내](https://help.yahoo.com/kb/finance/article-exchanges-data-delays-sln2310.html)에 따라 시장별 지연이 있을 수 있습니다. 화면에는 실제 시세 기준 시각과 조회 시각을 별도로 표시합니다.

### 월별 기록과 기존 데이터

투자 탭을 열면 마지막으로 저장된 보유 종목을 현재 월로 한 번 이월하고 현재 월만 갱신합니다. 과거 월은 수정하지 않습니다. 전월 대비는 동일 티커·통화의 직전 월 마지막 저장 수익률과의 차이(%p)이며, 비교 기록이 없으면 미표시합니다. 앱을 열지 않았던 월의 과거 시세나 월말 종가는 임의 생성하지 않습니다.

Phase 1 기록에 티커·통화·보유 수량이 없으면 그대로 유지하면서 별도 목록으로 표시합니다. 자동 조회 및 통화별 합산에는 포함하지 않습니다.

### 성장 규칙과 저장 데이터

| 누적 XP | 레벨 | 집 |
| --- | --- | --- |
| 0–499 | 1–5 | 아늑한 반지하 원룸 |
| 500–1,999 | 6–15 | 채광 좋은 오피스텔 |
| 2,000–4,999 | 16–30 | 역세권 투룸 아파트 |
| 5,000–9,999 | 31–49 | 한강뷰 펜트하우스 |
| 10,000 이상 | 50 이상 | 정원이 있는 대저택 |

각 구간 안에서 레벨 임계값을 균등 배분하고 정수로 올림합니다. 50레벨 이후에는 500 XP마다 한 레벨 상승합니다. `totalXp`는 누적 XP, `currentXp`는 현재 레벨 안에서 획득한 XP입니다.

LocalStorage 키 `rich-grandma-tycoon-v1`은 유지하고 저장 버전을 2로 올렸습니다. 구버전은 기존 공식 `100 × (level − 1) × level / 2 + currentXp`로 누적 XP를 복원한 뒤 새 규칙을 적용합니다. 아바타, 거래, 목표, 투자와 보상 이력은 보존합니다. 예를 들어 구버전 Lv.6 / 0 XP는 누적 1,500 XP, 새 규칙 Lv.12 / 100 XP로 표시됩니다.

### 보상 판정

`claimSettlement`는 버튼을 누른 시점의 상태로 조건을 다시 검사하고 캐릭터·XP 로그를 한 번에 저장합니다. 보상 종류와 기준 월/연도를 함께 확인하므로 같은 보상을 연속 클릭하거나 새로고침해도 다시 받을 수 없습니다.

| 보상 | 조건 | XP |
| --- | --- | --- |
| 일일 가계부 | 거래 날짜별 첫 기록 | 10 |
| 월간 예산 | 설정된 예산 코드가 있고 당월 지출 ≤ 예산 합계 | 150 |
| 월간 저축 | 저장한 당월 목표 저축액 이상 | 200 |
| 월간 투자 | 저장한 당월 목표 수익률 이상 | 200 |
| 연간 목표 | 연간 저축과 투자 목표 모두 달성 | 1,000 |

월간·연간 보상은 현재 월/연도를 대상으로 오늘까지의 거래를 집계하며 미래 거래는 제외합니다. 목표 미설정과 명시적으로 저장한 0원 목표를 구분합니다. 예산 보상은 월말까지 기다리지 않고 현재 조건을 충족하면 받을 수 있으며, 이후 지출이 늘어도 이미 받은 XP를 회수하지 않습니다.

환율 환산 없이 원화와 달러를 합산하지 않습니다. 투자 목표는 통화별 원금 가중 수익률이 각각 목표 이상이어야 충족합니다. 하나라도 시세가 미확인인 종목은 지급을 보류합니다. 연간 투자는 해당 연도 종목·통화별 최신 저장 평가액을 사용하며 같은 종목의 월별 평가액을 중복 합산하지 않습니다. 이 수익률은 매수 원금 대비 누적 수익률이며 연초 대비 수익률이나 실현 손익은 아닙니다.

표정은 예산 초과 시 찡그림, 오늘 XP 획득 또는 월간 목표 달성 시 웃음, 지난달 저축 목표 또는 확인된 투자 목표 미달 시 울음, 그 외 당월 기록이 있으면 덤덤, 기록이 없으면 기본 순서로 정합니다. 진행 중인 목표나 시세 미확인만으로 울음 상태가 되지 않습니다. 모든 표정에는 볼 터치를 유지합니다.

### 검증 범위

단위 테스트는 성장 경계값, 중복 보상 방지, 목표 조건과 미래 거래 제외, 통화별 투자 판정, 연간 스냅샷, 표정, 저장 데이터 이전을 검증합니다. 브라우저 테스트는 모바일·데스크톱에서 33개 파츠 선택, 5가지 표정, 저장·취소, 5단계 마이룸, XP 보상·이사·재로딩을 확인하며 기존 가계부·투자 흐름도 함께 확인합니다.

## Phase 5 영수증·결제 캡처 자동 입력

가계부의 **기록하기 → 영수증 캡처로 입력하기 → 결제 이미지 선택**에서 사용합니다. 이미지 선택 즉시 분석하며 **영수증을 꼼꼼히 읽고 있어요...**를 표시합니다. 분석이 끝나면 확인된 항목을 지출 폼에 자동으로 채웁니다. 날짜·금액·사용처·예산 코드를 수정하고 **기록 저장**을 눌러야 거래 및 일일 XP가 저장됩니다. 이미지 분석이나 자동 채움 자체로는 거래·XP를 생성하지 않습니다.

### 설정

`.env.example`을 참고해 프로젝트 루트의 `.env.local`에 다음 값을 설정한 뒤 Vite 개발 서버를 재시작합니다.

```dotenv
VITE_GEMINI_API_KEY=본인의_Gemini_API_키
VITE_GEMINI_MODEL=gemini-3.8-flash
```

사용자가 승인한 지원 모델로 기본값을 변경했습니다. 요청의 `gemini-1.5-flash`는 [Google 공식 변경 이력](https://ai.google.dev/gemini-api/docs/changelog)의 2025-09-29 항목에 종료가 명시되어 있습니다. 기본 모델은 [공식 모델 목록](https://ai.google.dev/gemini-api/docs/models)의 `gemini-3.8-flash`이며 환경변수로 교체할 수 있습니다. SDK는 요청대로 `@google/generative-ai`를 사용합니다. 이 SDK는 [공식 저장소](https://github.com/google-gemini/deprecated-generative-ai-js)에서 deprecated로 표시되어 있으므로 후속 SDK 전환 시 `receiptParser.ts`의 API 호출 부분을 교체할 수 있습니다.

**Vite의 `VITE_*` 값은 브라우저 번들에 포함됩니다.** `.gitignore`는 환경 파일의 커밋을 막지만 브라우저에서 키를 숨기지는 않습니다. 공개 서비스에서는 인증·사용량 제한을 갖춘 서버에서 키를 관리하고 브라우저가 해당 서버를 호출하도록 전환해야 합니다. 이번 구현은 요청한 클라이언트 환경변수 방식을 사용하며 실제 키를 생성하거나 다른 프로젝트 환경 파일에서 복사하지 않습니다.

### 파서 계약

`src/utils/receiptParser.ts`의 `parseReceiptImage(file, {signal?})`는 `ParseResult`를 반환합니다.

- `SUCCESS`: 양의 정수 원화 금액, 유효한 `YYYY-MM-DD`, 사용처, 허용 추천 코드가 모두 확인됨.
- `PARTIAL`: 필수 금액은 확인됐지만 다른 항목이 빠졌거나 유효하지 않음. 검증을 통과한 필드만 `data`에 반환.
- `FAILED`: 금액 누락·잘못된 금액·빈 JSON·파싱 실패·비정상 파일·설정 누락·네트워크/API 오류·시간 초과·취소. `data` 없이 친절한 `errorMessage` 반환.

AI의 원시 응답은 JSON 객체만 요청하고, 비결제 이미지나 금액을 모르면 `{}`를 요청합니다. 앱은 이 원시 `{}`를 `FAILED` 상태로 변환합니다. 알 수 없는 필드, 존재하지 않는 날짜, 임의 추천 코드는 버립니다. 이미지 속 명령은 무시하도록 시스템 프롬프트에 명시합니다. 이 기능은 원화 지출 한 건을 대상으로 하며 외화·환불·여러 거래가 섞인 이미지는 직접 입력으로 안내하도록 프롬프트를 구성했습니다. AI 결과는 오인식 가능성이 있으므로 저장 전에 사용자가 검토합니다.

`FO01`, `SH01`, `TR01`, `CU01` 중 추천합니다. 기존 여가 프리셋 `LE01 · 문화/여가`는 `CU01` 추천과 연결하되 저장된 코드나 과거 거래는 변경하지 않습니다. 현재 설정에 없는 추천 코드는 드롭다운을 비워 직접 선택하게 합니다. 날짜·메모가 누락되면 기존 폼 값을 유지하고 확인이 필요한 항목을 명시합니다.

### 예외 처리와 이미지 수명

`src/components/ReceiptImportSheet.tsx`는 모바일 BottomSheet와 데스크톱 모달로 동작합니다. 키보드 포커스는 모달 안에 유지하며 Escape는 영수증 화면만 닫고 작성 중인 가계부는 유지합니다. JPG/PNG/WEBP를 6MB까지 허용하고 MIME 형식과 파일 시그니처를 검사합니다. HEIC·빈 파일·초과 용량은 네트워크 전송 전에 안내합니다.

이미지를 선택하면 Google Gemini로 전송하며 파일 선택 전에 화면에 안내합니다. `accept="image/*"` 파일 선택기를 사용하고 지원하지 않는 형식은 친절한 오류로 처리합니다. `resizeReceiptImage(file, signal?)`는 브라우저에서 이미지를 디코딩한 뒤 Canvas로 가로 최대 800px, 원본 비율 유지, 작은 이미지 확대 없이 리사이징합니다. 투명 배경은 흰색으로 합성하고 JPEG 품질 0.9의 Base64로 변환하여 `{data, mimeType, width, height}`를 반환합니다. API에는 이 변환 결과만 전달합니다. 손상된 이미지, Canvas 실패도 수동 입력 안내로 처리합니다. 앱은 이미지·base64·원시 응답을 LocalStorage에 보관하지 않습니다. 미리보기 URL은 교체·닫기 시 해제합니다. 최대 25초 제한, 취소, 파일 교체, 화면 종료 시 중단과 오래된 응답 무시를 적용했습니다. 이미 서버에 전달된 요청은 브라우저 취소만으로 서버 처리·과금까지 중단된다고 보장하지 않습니다. 자동 재시도는 하지 않으며 사용자가 다시 읽기를 선택할 수 있습니다.

### 검증

실제 브라우저 Canvas 테스트는 전송 이미지의 800px 축소, 종횡비, 작은 이미지 크기 유지, 투명 배경의 흰색 합성과 손상된 이미지의 전송 차단을 검증합니다. 단위 테스트는 응답 검증, 윤년 날짜, 부분 결과, 금액 누락, 코드 연결, 파일 제한, API 오류, 시간 초과·취소를 확인합니다. Playwright는 실제 Gemini SDK의 HTTP 요청을 모의 응답으로 처리하고 성공·부분·실패·할당량 초과·늦은 응답·Escape·수정·명시적 저장 및 XP를 데스크톱/모바일에서 확인합니다. 테스트 서버의 API 키는 가짜 값입니다. 실제 Gemini 키로 이미지 인식 정확도나 계정별 모델 사용 가능 여부를 검증한 것은 아닙니다.

## Phase 6 할미의 소비 피드백과 CSV 백업

통계 탭 상단의 **이번 달 할미의 잔소리 듣기** 버튼은 선택 월의 예산 한도 합계, 지출 합계, 지출이 가장 큰 코드·카테고리, 투자 수익률을 모아 Gemini에 전달합니다. 개별 메모나 거래 목록은 보내지 않습니다. USD와 KRW 수익률은 환산해 더하지 않고 따로 표시하며, 해당 월의 보유 종목 시세가 하나라도 확인되지 않으면 수익률을 전달하지 않습니다. 피드백은 정확히 세 문장인지 확인한 뒤 캐릭터 말풍선에 보여줍니다. API 키 누락·요청 제한·네트워크 오류에는 재시도 안내를 표시합니다. 요청을 전송하는 통계 버튼에는 API 키가 설정되어 있어야 합니다.

요청 모델은 기존 Phase 5와 함께 `VITE_GEMINI_MODEL`을 사용하고 기본값은 `gemini-3.8-flash`입니다. 종료된 Gemini 1.5 모델을 새 기능의 기본 모델로 지정하지 않습니다.

목표 & 설정 탭 하단의 **가계부 데이터 백업하기 (CSV)** 버튼은 전체 거래를 `가계부백업_YYYYMMDD.csv`로 내려받습니다. UTF-8 BOM과 CRLF 줄바꿈으로 한글 스프레드시트 호환을 높였고, 날짜순·동일 날짜 ID순으로 정렬합니다. 사용자가 입력한 메모와 카테고리명은 CSV 인용·이스케이프하고 스프레드시트 수식 시작 문자를 안전하게 처리합니다. 거래가 없어도 헤더만 있는 파일을 받을 수 있습니다.
