## 남은 위험과 우선순위

1. **높음 — XP 신뢰 경계:** 계정별 저장 API가 클라이언트의 `character.totalXp`와 `xpLogs`를 구조만 확인하고 받아들인다. 브라우저 요청을 조작하면 XP·등급을 임의로 올릴 수 있다. 보상 지급과 점수 계산을 서버 액션으로 옮기고 이력을 서버에서 검증해야 한다.
2. **높음 — 저장 충돌 복구:** 다른 기기가 먼저 계정 데이터를 저장하면 버전 충돌을 정확히 탐지하지만, 현재 화면의 `다시 저장` 버튼은 같은 낡은 버전으로 재시도해 계속 실패한다. 새로고침 전 미저장 데이터를 내보내거나 안전하게 병합할 수 있는 복구 흐름이 필요하다.
3. **운영 확인 필요 — 관리자 초기 설정:** 실서버의 `/admin/setup` 페이지는 열리지만, `admin-setup` API는 여전히 `admin_setup_unavailable`(503)을 반환한다. `ADMIN_SETUP_TOKEN`의 Production 적용, 값 길이(32~256자), 실제 배포 대상을 확인해야 한다. 관리자 계정 생성 완료는 확인되지 않았다.
4. **외부 의존 — AI·시세:** 공개 시세·환율 API는 이번 점검에서 응답했지만 영수증과 월간 AI 피드백은 인증된 실서버 계정으로 재검증하지 않았다. Yahoo·Gemini 가용성과 응답 지연은 운영 모니터링이 필요하다.

일반 회원가입은 유지하고 관리자 생성 링크만 공개 로그인 화면에서 숨긴 상태다.
