# 가계부 웹 전용 스타일 가이드

작성일: 2026-10-07  
기준 화면: 1280 × 900px  
관련 기능 문서: [web-redesign-functional-spec.md](./web-redesign-functional-spec.md)

## 1. 디자인 방향

현재 모바일 앱은 카드가 세로로 이어지는 구조다. 웹 버전은 같은 카드를 넓게 펼치는 방식이 아니라, 정보 밀도와 작업 흐름을 우선하는 업무용 재무 대시보드로 재구성한다.

웹 버전의 핵심 인상:

- 한 화면에서 요약과 다음 작업을 판단할 수 있는 정보 밀도
- 고정 내비게이션과 넓은 콘텐츠 캔버스
- 카드 나열보다 표·분할 패널·요약 수치 중심
- 큰 제목보다 명확한 계층과 정렬선 중심
- 파란색은 주요 행동과 선택 상태에만 사용
- 금액·날짜·상태가 빠르게 비교되는 숫자 중심 UI

피해야 할 형태:

- 모바일 전화기 프레임
- 상단 상태 표시줄을 휴대폰처럼 보이게 하는 시계·신호 아이콘
- 모든 내용을 둥근 카드로 감싸는 구성
- 모바일 하단 탭을 데스크톱에서 좌측으로 단순 회전한 구성
- 빈 공간이 큰 랜딩 중심 배치
- 인라인 스타일로 화면마다 제각각 달라지는 버튼과 폼

## 2. 1280px 캔버스와 레이아웃

### 기준 치수

```text
브라우저 viewport             1280px
좌우 외부 여백                 24px
웹 앱 전체 폭                 1232px
사이드바 폭                   224px
콘텐츠 영역                   1008px
콘텐츠 내부 좌우 패딩          32px
실제 콘텐츠 폭                 944px
```

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  글로벌 헤더 64px                                                     사용자 │
├───────────────┬──────────────────────────────────────────────────────────────┤
│               │  페이지 제목 / 설명                         기간·주요 액션    │
│  사이드바      ├──────────────────────────────────────────────────────────────┤
│  224px        │  핵심 요약 영역                                            │
│               ├───────────────────────────────┬──────────────────────────────┤
│               │  주요 작업/차트                │  보조 요약/상태                │
│               ├───────────────────────────────┴──────────────────────────────┤
│               │  전체 폭 테이블 또는 최근 활동                               │
└───────────────┴──────────────────────────────────────────────────────────────┘
```

### 화면 폭 규칙

| 구간 | 동작 |
|---|---|
| 1200px 이상 | 224px 사이드바 + 콘텐츠 2열/3열 구성 |
| 1024–1199px | 사이드바 200px, 콘텐츠 1–2열 |
| 768–1023px | 사이드바 축소 또는 접기, 주요 표는 가로 스크롤 |
| 767px 이하 | 별도 모바일 레이아웃으로 전환 |

1280px에서는 `max-width`를 무작정 줄여 모바일 카드처럼 보이게 하지 않는다. 콘텐츠가 짧은 페이지도 화면 중앙의 좁은 카드가 아니라, 웹 앱 셸 안에서 일관된 시작선과 폭을 사용한다.

## 3. 디자인 토큰

### 색상

| 토큰 | 값 | 사용 |
|---|---|---|
| `--web-bg` | `#F5F7FA` | 브라우저 및 콘텐츠 배경 |
| `--web-surface` | `#FFFFFF` | 헤더, 패널, 표 |
| `--web-sidebar` | `#111827` | 데스크톱 사이드바 |
| `--web-sidebar-muted` | `#9CA3AF` | 비활성 사이드바 텍스트 |
| `--web-primary` | `#2563EB` | 주요 버튼, 선택, 링크 |
| `--web-primary-dark` | `#1D4ED8` | hover/pressed |
| `--web-primary-soft` | `#EFF6FF` | 선택 배경, 정보 강조 |
| `--web-text` | `#111827` | 본문 및 제목 |
| `--web-text-muted` | `#6B7280` | 보조 설명 |
| `--web-text-faint` | `#9CA3AF` | placeholder, 보조 숫자 |
| `--web-border` | `#E5E7EB` | 구분선, 입력 테두리 |
| `--web-income` | `#15803D` | 수입, 증가 |
| `--web-expense` | `#DC2626` | 지출, 초과, 삭제 |
| `--web-warning` | `#D97706` | 주의, 예산 80% 이상 |
| `--web-info` | `#0891B2` | 안내, 동기화 |

색상 사용 규칙:

- 한 화면에서 주 강조색은 파란색 1개만 사용한다.
- 수입은 초록, 지출은 빨강을 사용하되 넓은 배경색으로 칠하지 않는다.
- 색상만으로 상태를 전달하지 않고 텍스트·아이콘·상태 라벨을 함께 표시한다.
- 전체 배경과 패널의 명도 차이는 작게 유지하고, 구분은 여백과 선으로 한다.

### 타이포그래피

폰트 스택: `Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`

| 역할 | 크기 | 굵기 | 행간 |
|---|---:|---:|---:|
| 페이지 제목 | 24px | 700 | 1.3 |
| 섹션 제목 | 16px | 700 | 1.4 |
| 패널 제목 | 14px | 700 | 1.4 |
| 본문 | 14px | 400 | 1.5 |
| 표 본문 | 13px | 400 | 1.4 |
| 보조 설명 | 12px | 400 | 1.5 |
| 숫자 강조 | 28px | 700 | 1.1 |
| 대시보드 핵심 숫자 | 32px | 700 | 1.1 |
| 라벨/상태 | 11px | 600 | 1.3 |

금액은 우측 정렬하고 `font-variant-numeric: tabular-nums`를 사용한다. 제목과 본문은 과도한 자간 음수를 적용하지 않는다.

### 간격과 모서리

```text
4px   아이콘과 텍스트 사이의 최소 간격
8px   작은 요소 간격
12px  폼 필드 내부·표 셀 여백
16px  패널 내부 기본 여백
24px  패널 간격
32px  콘텐츠 좌우 패딩
40px  주요 섹션 간격
```

- 기본 패널 모서리: 10px
- 버튼·입력 모서리: 7px
- 상태 배지 모서리: 999px
- 카드 그림자: 기본적으로 사용하지 않고 `border: 1px solid var(--web-border)` 사용
- 부유 모달만 `0 16px 40px rgba(15,23,42,.16)` 그림자 사용

## 4. 공통 웹 셸

### 글로벌 헤더

높이 64px, 배경 흰색, 하단 1px 선.

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  ₩ 가계부             현재 위치: 대시보드                 도움말  알림  홍길동 ▾ │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 좌측 로고는 `₩` 아이콘과 서비스명으로 구성한다.
- 현재 위치는 breadcrumb 또는 페이지 제목으로 보조한다.
- 우측에는 사용자명, 계정 메뉴, 로그아웃을 둔다.
- 모바일 전용 시계·신호 아이콘은 제거한다.

### 사이드바

배경 `#111827`, 폭 224px, 헤더 아래 전체 높이.

```text
┌─────────────────┐
│  메뉴            │
│                 │
│  ▣ 대시보드      │  ← 선택 시 파란색 배경 4px 포인트
│  ≡ 가계부        │  ← 펼침/접힘 가능한 메뉴 그룹
│    월간 요약     │
│    원자료 내역   │
│    ＋ 새 입력    │  ← 가계부 하위 주요 액션
│  ◇ 자산 현황     │
│                 │
│  설정            │
│  ⚙ 환경 설정     │
│                 │
│  ─────────────── │
│  현재 계정       │
│  @user           │
└─────────────────┘
```

- 메뉴 항목 높이 42px, 좌우 패딩 12px.
- 선택 메뉴는 배경 `#1E40AF`, 왼쪽 3px 파란 포인트, 흰색 텍스트.
- `가계부`는 펼침 가능한 그룹 메뉴로 구성하고 `월간 요약`, `원자료 내역`, `새 입력`을 하위 메뉴로 둔다.
- `새 입력`은 사이드바에서 파란색 Primary 항목으로 강조하되, 화면 안에서 떠다니는 원형 플로팅 버튼은 사용하지 않는다.
- 관리자 셸은 사용자 메뉴를 숨기고 회원 관리 메뉴만 표시한다.
- 사이드바의 메뉴 구조는 다음처럼 고정한다.

```text
대시보드
가계부
  ├─ 월간 요약
  ├─ 원자료 내역
  └─ 새 입력
자산 현황
설정
```

`새 입력`은 기능상 `/app/ledger/input`으로 관리한다. 별도의 최상위 메뉴로 중복 노출하지 않는다.
- 관리자 셸은 사용자 메뉴를 숨기고 회원 관리 메뉴만 표시한다.

### 콘텐츠 헤더

페이지마다 다음 순서를 고정한다.

```text
페이지 제목          설명 문구
                                      기간 선택   보조 액션   주요 액션
```

페이지 제목과 액션이 같은 행에 있고, 제목 아래에 긴 빈 공간을 만들지 않는다.

### 새 입력 버튼 위치

새 입력은 사용자가 어디에서 시작하든 찾을 수 있어야 하지만, 화면마다 버튼을 반복해 시각적 우선순위를 흐리지 않는다.

| 위치 | 표시 여부 | 역할 |
|---|---|---|
| 사이드바 `가계부 > 새 입력` | 항상 | 전체 화면에서 접근하는 기본 진입점 |
| 가계부 페이지 헤더 우측 | 항상 | 가계부를 보고 바로 입력하는 주요 액션 |
| 대시보드 헤더 우측 | 보조 표시 | 최근 거래를 본 뒤 입력으로 이어지는 빠른 이동 |
| 새 입력 페이지 헤더 | 현재 위치 표시 | `새 입력` 버튼을 다시 보여주지 않고 저장·일괄입력 표시 |

가계부 페이지 헤더:

```text
월간 가계부                                  [2026년 10월 ▾] [＋ 새 입력]
월별 수입·지출과 원자료를 관리합니다.
```

- Primary 버튼은 `＋ 새 입력` 하나만 둔다.
- 월 선택은 Secondary 컨트롤로 왼쪽에 배치한다.
- 페이지 하단이나 화면 우측에 고정되는 플로팅 버튼은 사용하지 않는다.
- 입력 페이지에서는 상단 우측에 `[엑셀 일괄입력] [저장]`을 배치한다.

## 5. 컴포넌트 스타일

### 버튼

| 종류 | 높이 | 스타일 |
|---|---:|---|
| Primary | 40px | 파란 배경, 흰색 글자 |
| Secondary | 40px | 흰색 배경, 회색 테두리 |
| Ghost | 36px | 배경 없음, 파란색 글자 |
| Danger | 36px | 연한 빨강 배경, 빨강 글자 |
| Icon | 32px | 정사각형, tooltip 제공 |

- 버튼 텍스트는 13px, 굵기 600.
- 한 행에 Primary 버튼은 1개만 둔다.
- 삭제는 Danger 버튼을 사용하고 즉시 삭제하지 않고 확인 모달을 거친다.
- 로딩 중에는 텍스트를 `처리 중…`으로 바꾸고 중복 클릭을 막는다.

### 입력 필드

- 높이 40px, 글자 13px, 내부 좌우 패딩 12px.
- 라벨은 입력 위에 11px/600으로 표시한다.
- placeholder는 실제 라벨을 대신하지 않는다.
- focus 시 파란 1px 테두리와 3px 연한 파란 외곽선을 사용한다.
- 오류 시 필드 테두리·오류 문구를 빨강으로 표시한다.
- 숫자·금액 입력은 우측 정렬한다.

### 패널

```text
패널 padding       20px
패널 제목 하단     16px
패널 간격          24px
패널 border        1px solid #E5E7EB
패널 radius        10px
```

패널 안에 또 다른 패널을 반복해서 중첩하지 않는다. 하위 정보는 구분선과 섹션 제목으로 나눈다.

### 테이블

- 헤더 높이 40px, 배경 `#F9FAFB`, 텍스트 11px/600.
- 본문 행 높이 52px 이상.
- 이름·상태는 좌측 정렬, 금액·날짜·액션은 우측 또는 중앙 정렬.
- hover 행은 `#F8FAFC`.
- 행 선택이 필요할 때만 체크박스를 추가한다.
- 작은 화면에서는 컬럼 우선순위를 정해 부가 컬럼부터 숨긴다.

관리자 회원 표:

```text
회원명       아이디       전화번호       가입일        상태       액션
홍길동       @hong        010-****-1234  2026.10.07    정상       보기 · 삭제
```

### 배지와 상태

- 상태 배지는 텍스트를 포함한다: `정상`, `동기화 중`, `오류`, `초과`.
- 배지 높이 24px, 좌우 8px, 글자 11px.
- 수입·지출은 배지보다 금액 색상과 작은 라벨을 우선한다.

### 차트

- 차트는 패널의 보조 정보이며 숫자 표기를 대체하지 않는다.
- 도넛 차트 옆에는 항목명·금액·비율을 수직 목록으로 표시한다.
- 범례 색상은 기존 대분류 색상을 재사용하되, 채도를 낮춘다.
- 차트 데이터가 없으면 빈 차트 대신 `이번 달 데이터가 없습니다`를 표시한다.

### 모달과 알림

- 모달 폭 480–560px, 화면 중앙 정렬, 배경 dim 40%.
- 제목·설명·입력·액션 순서로 구성한다.
- toast는 화면 우측 하단에 320px 이하 폭으로 표시한다.
- 오류는 toast만 사용하지 않고 원인이 있는 필드나 패널에도 표시한다.

## 6. 페이지별 스타일 구조

### 로그인

```text
┌───────────────────────────────┬──────────────────────────────────────────────┐
│                               │                                              │
│  ₩ 가계부                      │             로그인 패널                       │
│  돈의 흐름을 한눈에             │  로그인                                     │
│                               │  아이디 [________________________]           │
│  • 월별 지출 분석              │  비밀번호 [______________________]           │
│  • 자산·부채 관리              │  [                 로그인                 ]   │
│  • 예산 집행률 확인             │  아이디 찾기  ·  비밀번호 찾기  · 회원가입    │
│                               │                                              │
└───────────────────────────────┴──────────────────────────────────────────────┘
```

- 전체 화면을 좌우 5:7 정도로 분할한다.
- 로그인 패널은 흰색 배경, 테두리, 10px radius의 고정 폭 420px이다.
- 로그인 화면에는 사이드바와 하단 탭을 표시하지 않는다.

### 관리자 회원 관리

```text
제목: 회원 관리                         [회원 검색________________] [새로고침]
설명: 등록된 계정과 데이터 접근 상태를 확인합니다.

[전체 회원  24] [이번 달 신규  4] [전화번호 등록  21]

회원 목록
┌──────────────────────────────────────────────────────────────────────────────┐
│ 회원명 | 아이디 | 연락처 | 가입일 | 마지막 상태 | 데이터 보기 | 삭제          │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 기존 세로 카드 목록을 테이블로 변경한다.
- 검색은 이름·아이디를 동시에 검색한다.
- 회원 데이터 보기는 현재 관리자 화면 안에서 상세 패널 또는 별도 route로 연다.

### 사용자 대시보드

```text
대시보드                         2026년 10월 ▾        [원자료 입력]

[순자산 ₩00,000,000] [수입 ₩0] [지출 ₩0] [현금흐름 +₩0]

┌───────────────────────────────┐ ┌───────────────────────────────────────────┐
│ 자산 구성                       │ │ 이번 달 대분류별 합계                     │
│ 차트 + 범례                    │ │ 막대 그래프 + 금액                       │
└───────────────────────────────┘ └───────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────────────────────┐
│ 최근 거래                                                                  › │
│ 날짜 | 항목 | 분류 | 금액                                                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 가계부

- 상단 요약은 가로 3칸으로 고정한다.
- 차트와 대분류 비교는 5:7 비율로 배치한다.
- 원자료는 카드가 아니라 테이블을 기본으로 한다.
- 페이지 우측 상단에는 `＋ 새 입력`을 둔다.
- 입력·수정 액션은 페이지 우측 상단과 테이블 행 액션에 중복 제공한다.

### 원자료 입력

- 입력 화면은 카드가 여러 장 쌓이는 형태가 아니라 행 기반 편집 영역으로 구성한다.
- 필드 순서: 날짜 → 항목명 → 대분류 → 카테고리 → 금액 → 메모.
- 대량 입력은 별도 모달이 아니라 페이지 상단의 보조 액션으로 연다.
- 저장 버튼은 화면 우측 상단에 고정하고, 미저장 변경이 있으면 페이지 이탈 경고를 제공한다.

## 7. 반응형 규칙

웹 기준 구조는 1280px에서 먼저 완성한 뒤 아래 순서로 줄인다.

- 1024px: 사이드바 200px, 대시보드 2열 유지
- 900px: 대시보드 보조 패널을 1열로 전환
- 768px: 사이드바를 접힌 아이콘 메뉴로 변경, 표의 보조 컬럼 숨김
- 767px 이하: 모바일 전용 구조로 전환

모바일 breakpoint를 위해 데스크톱 구성의 요소 순서를 변경하지 않는다. 각 화면은 `web-shell`과 `mobile-shell`의 표현 규칙을 분리한다.

## 8. 접근성과 상호작용

- 본문 대비율 WCAG AA를 목표로 한다.
- 키보드 Tab 순서가 좌측 메뉴 → 페이지 액션 → 본문 → 하단 액션 순으로 이어진다.
- 모든 아이콘 버튼에는 accessible label 또는 tooltip을 제공한다.
- Enter는 제출, Escape는 모달 닫기로 동작한다.
- 포커스 링을 제거하지 않는다.
- hover만으로 중요한 정보를 전달하지 않는다.
- 삭제·초기화·로그아웃은 확인 또는 취소 가능한 흐름을 제공한다.
