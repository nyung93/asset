# 가계부 웹 전용 재구성 기능 정의서

작성일: 2026-10-07  
대상 저장소: `nyung93/asset`  
목표 기준 해상도: 1280px 데스크톱

## 1. 문서 목적

현재 앱은 모바일 화면을 기준으로 만든 단일 화면 구조를 데스크톱에 확장한 상태다. 다음 UI 구현에서는 모바일 프레임을 키우는 방식 대신, 웹 서비스에 맞는 공통 셸·라우팅·화면 계층을 새로 구성한다.

이번 문서는 화면 구현 전에 확정해야 할 기능, 화면 구성, 상태 전환, 데이터 요구사항과 검수 기준을 정의한다.

## 2. 현재 구현 기준

### 데이터 저장소

| 영역 | 현재 방식 |
|---|---|
| 회원 계정 | Firestore `accounts/{userId}` |
| 사용자 재무 데이터 | Firestore `userdata/{userId}` |
| Firebase 설정 | `VITE_FIREBASE_*` 빌드 환경변수 |
| 로컬 캐시 | `sessionStorage`, `localStorage` |
| 관리자 인증 | 클라이언트 코드의 특수 관리자 조건 |

### 현재 제공 기능

- 랜딩, 로그인, 회원가입, 아이디 찾기, 비밀번호 찾기
- 관리자 회원 목록, 검색, 회원 삭제, 회원 데이터 보기, 회원 정보 복사
- 대시보드: 순자산, 월 수입·지출, 자산 구성, 대분류 합계, 최근 입력
- 월간 가계부: 수입·지출·잔액, 지출 도넛 차트, 대분류별 전월 대비, 예산 집행률
- 원자료 입력: 단건 입력, 다건 초안, 엑셀 일괄입력
- 자산 현황: 자산 유형별 관리, 잔액 수정, 체크 상태, 삭제
- 마이페이지: 프로필, 재무 목표, 카테고리 관리, 예산 관리, 데이터 초기화, 로그아웃
- 원자료 상세 보기: 날짜·대분류·카테고리 필터와 페이지 이동

## 3. 우선 해결할 결함

### 3.1 로그인 후 로그인 화면 잔류

현재 화면 전환은 `state.screen`과 여러 `screen` DOM의 `active` 클래스를 동시에 관리한다. 웹 전용 화면에서는 인증 화면과 로그인 후 앱 셸을 분리해, 로그인 성공 시 인증 셸이 DOM·레이아웃·포커스에서 완전히 제거되도록 한다.

검수 기준:

- 정상 사용자 로그인 성공 후 로그인 폼이 화면에 남지 않는다.
- 관리자 로그인 성공 후 관리자 화면만 표시된다.
- 로그인 실패 시 현재 화면에 오류 메시지를 표시하고 입력값을 보존한다.
- 로딩 중에는 로그인 버튼을 중복 실행할 수 없다.
- 새로고침 시 유효한 로그인 상태는 대상 화면으로 복원하고, 무효하거나 만료된 상태는 로그인 화면으로 이동한다.
- 브라우저 뒤로가기·앞으로가기로 이전 화면이 중첩 표시되지 않는다.
- 로그아웃 후 브라우저 뒤로가기로 인증된 화면에 재진입할 수 없다.

### 3.2 인증 책임 분리

현재 관리자 비밀번호가 클라이언트 번들에 포함되는 구조는 웹 배포에 부적합하다. 1차 웹 재구성에서는 관리자 화면 진입 UI를 유지하되, 다음 단계에서 관리자 인증을 서버 검증 또는 Firebase Authentication + 권한 정보로 이전한다.

- 관리자 비밀번호를 화면 코드에 추가로 노출하지 않는다.
- 관리자 라우트는 일반 회원 데이터 화면과 분리한다.
- 인증 실패·권한 없음·세션 만료 상태를 서로 다른 화면 상태로 처리한다.

## 4. 웹 전용 정보 구조

### 공개 영역

```text
PublicShell
├── 랜딩
├── 로그인
├── 회원가입
└── 계정 찾기
    ├── 아이디 찾기
    └── 비밀번호 찾기
```

### 관리자 영역

```text
AdminShell
├── 관리자 대시보드
├── 회원 관리
│   ├── 회원 검색
│   ├── 회원 상세/재무 데이터 보기
│   ├── 회원 정보 복사
│   └── 회원 삭제
└── 관리자 로그아웃
```

### 사용자 영역

```text
AppShell
├── 대시보드
├── 가계부
│   ├── 월간 요약
│   ├── 원자료 목록
│   ├── 원자료 상세/필터
│   └── 새 입력
├── 자산 현황
└── 설정
    ├── 프로필
    ├── 예산 관리
    ├── 카테고리 관리
    ├── 재무 목표
    ├── 데이터 초기화
    └── 로그아웃
```

## 5. 1280px 웹 화면 구성

### 공통 웹 셸

- 전체 배경은 밝은 회색, 콘텐츠 영역은 최대 1200px로 제한한다.
- 상단에는 서비스 로고, 현재 사용자, 알림 자리, 로그아웃을 배치한다.
- 좌측 고정 사이드바에 주요 메뉴와 `원자료 입력` 주요 액션을 둔다.
- 콘텐츠는 `페이지 제목 → 핵심 요약 → 주요 작업 → 보조 정보` 순서로 구성한다.
- 모바일용 전화기 프레임, 상태 표시줄, 하단 탭을 웹 화면에서 사용하지 않는다.
- 긴 목록은 페이지 내부 스크롤을 사용하되, 전체 페이지가 가로로 밀리지 않도록 한다.

### 로그인 화면

- 좌측: 서비스 소개, 핵심 기능 3개, 보안/데이터 안내
- 우측: 로그인 카드
- 카드 구성: 아이디, 비밀번호, 로그인, 아이디 찾기, 비밀번호 찾기, 회원가입
- 로그인 오류는 입력 카드 내부에 표시한다.
- Enter 키로 로그인할 수 있다.
- 1280px에서 카드가 수직·수평으로 안정적으로 중앙 정렬된다.

### 관리자 화면

- 상단: `관리자 / 회원 관리`, 검색, 로그아웃
- 요약 카드: 전체 회원, 이번 달 신규, 전화번호 등록
- 회원 테이블: 이름, 아이디, 전화번호, 가입일, 데이터 보기, 정보 복사, 삭제
- 1280px에서는 카드 목록보다 표 형태를 우선한다.
- 검색 결과 없음, 로딩, 삭제 확인, 삭제 실패 상태를 각각 제공한다.

### 사용자 대시보드

- 상단 요약 카드: 순자산, 이번 달 수입, 이번 달 지출, 현금흐름
- 2열 콘텐츠: 자산 구성 / 대분류별 합계
- 하단 전체 폭: 최근 거래
- 각 카드에서 관련 상세 화면으로 이동할 수 있어야 한다.

### 가계부 화면

- 상단에 연도·월 선택과 월간 수입·지출·잔액을 둔다.
- 좌측에는 지출 구성 차트, 우측에는 대분류별 합계와 전월 대비를 둔다.
- 하단에는 예산 집행률과 원자료 테이블을 둔다.
- 원자료 행 액션은 수정·삭제·상세 보기로 통일한다.

### 원자료 입력 화면

- 기본은 테이블형 입력으로 제공한다.
- 행 추가, 행 삭제, 저장, 엑셀 일괄입력을 상단 액션으로 제공한다.
- 필수값 오류는 행 단위로 표시한다.
- 저장 중·저장 성공·저장 실패 상태를 명확히 표시한다.

### 자산·설정 화면

- 자산 현황은 유형별 요약과 자산 테이블을 함께 제공한다.
- 설정은 프로필, 예산, 카테고리, 목표, 초기화를 섹션 또는 탭으로 구분한다.
- 파괴적 작업은 확인 모달과 완료 알림을 사용한다.

## 6. 화면 상태 규칙

모든 웹 화면은 다음 상태를 갖는다.

1. `loading`: 최초 로드 또는 저장 중
2. `ready`: 정상 표시
3. `empty`: 데이터 없음
4. `error`: 읽기·쓰기 실패
5. `unauthorized`: 로그인 필요 또는 권한 없음

화면 전환은 단일 라우터 상태가 담당하고, 각 화면 컴포넌트가 다른 화면의 `display`나 `active` 클래스를 직접 조작하지 않도록 한다.

권장 라우트:

```text
/login
/signup
/find-account
/admin
/app/dashboard
/app/ledger
/app/ledger/input
/app/assets
/app/settings
/app/ledger/detail
```

Vercel에서 새로고침 후에도 라우트가 동작하도록 SPA fallback 설정을 함께 검토한다.

## 7. 구현 원칙

- 화면 구조와 데이터 로직을 분리한다.
- 인라인 스타일 대신 화면별 CSS와 재사용 컴포넌트 스타일을 사용한다.
- 기존 Firestore 컬렉션과 데이터 필드의 호환성을 유지한다.
- 모바일은 별도 breakpoint로 축소하는 보조 레이아웃으로 유지하되, 웹 화면을 기준 구조로 삼는다.
- `dist/`, `node_modules/`는 커밋하지 않는다.
- 실제 기능을 바꾸기 전에 문서의 기능·상태·검수 기준을 먼저 갱신한다.

## 8. 구현 단계

### 1단계: 라우팅·인증 셸

- 인증/관리자/사용자 셸 분리
- 로그인 성공·실패·로그아웃·새로고침·뒤로가기 검증
- 로그인 화면 잔류 결함 해결

### 2단계: 웹 공통 레이아웃

- 1280px 기준 헤더·사이드바·콘텐츠 폭 구성
- 공통 카드, 테이블, 버튼, 모달, 알림 스타일 구성

### 3단계: 관리자 화면

- 회원 관리 테이블과 상세 데이터 화면 구성
- 검색·삭제·복사·상태 처리

### 4단계: 사용자 핵심 화면

- 대시보드, 가계부, 원자료 입력, 자산 현황

### 5단계: 설정·예외 상태·반응형

- 마이페이지 기능 이전
- 빈 상태·오류·로딩·권한 상태 보완
- 1024px, 768px, 모바일 검수

## 9. 완료 기준

- 1280px에서 로그인 화면이 수평·수직으로 안정적으로 표시된다.
- 사용자 로그인 후 로그인 화면이 남지 않고 대시보드로 전환된다.
- 관리자 로그인 후 관리자 셸만 표시된다.
- 새로고침과 뒤로가기가 현재 인증 상태와 일치한다.
- 관리자 회원 관리의 기존 기능이 모두 동작한다.
- 기존 회원·거래·자산 데이터가 손실 없이 표시된다.
- 1280px, 1024px, 모바일에서 가로 스크롤이 발생하지 않는다.
- `npm run build`가 성공하고, 실제 브라우저에서 핵심 사용자·관리자 흐름을 통과한다.
